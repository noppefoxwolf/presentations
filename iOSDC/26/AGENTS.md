# iOSDC 2026 作業指示

Deckset原稿を編集する前に、必ず `PROJECT_MEMORY.md` と `GLOSSARY.md` を読み、既存の判断と用語を確認する。

- 判断、草稿、コード例はチャットだけに残さず、Markdownファイルへ記録する。
- ユーザーが指定したDeckset原稿をアクティブなデッキとして扱う。指定がなければ `iosdc2.md` を使う。
- `DRAFT_NOTES.md` は保持用の非スライド作業資料。採用しなかった構造案、重要なコード案、大きな表現変更の要点を残す。旧稿の全文を複製する必要はない。
- Decksetでは `---` をスライド区切り、`^` で始まる段落を話者ノートとして使う。
- 最終レビューではMarkdown全体ではなく `^` 話者ノートだけから時間を見積もり、登壇時間を約45分に整える。
- `iosdc.md` は変更しない。
- プレゼンテーションの用語や表現を改訂するときは、現在のスライドだけでなく原稿全体を検索し、同じ語や近い表現も必要に応じて一貫して更新する。
- 「保つもの／変えるもの」のような不自然に抽象的なラベルは避け、意図する区別には「変わらないもの／表示条件に合わせて変えるもの」のような具体的で自然な日本語を使う。コンテナとプラットフォームを区別する箇所では、それぞれの語を明示する。
- 話者ノートの遷移は見出し階層に合わせ、章の入口では全体の流れと次のテーマを示し、中テーマ・小テーマの入口では直前の内容から続く理由だけを短く添える。すべてのスライドに機械的な案内を加えない。45分程度のトークでは、現在地を示すため章・節の入口の表示見出しにだけ番号を付けてよい。
- 聴衆向けの表示本文と話者ノートでは、スライド番号やページ番号を参照しない。番号の代わりに、扱った考え方や直前の内容を自然に指す。
- 「ここでの問いは」のような抽象的なプロセス表現は避け、聴衆が注目・検討する内容を直接、自然な話し言葉で述べる。実質的な問いかけが有効な場合は残す。
- トークのタイトルは、ユーザーから明示的な依頼がない限り変更しない。
