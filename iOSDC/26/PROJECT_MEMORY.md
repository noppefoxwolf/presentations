## プレゼンテーションの形式・内容

プレゼンテーションの内容は、主に Markdown のテキストファイルとして作成・管理する。
Deckset向けに、スライドは `---` で区切り、`^` で始まる段落はスライドに表示しない話者ノートとして扱う。

## 現在の確定方針

- 登壇時間の目標は約45分。
- UIの構造とUIのモデリングは、ひとつの章に統合する。
- 「ifをやめる」／仮想的な複雑化を避ける判断フレームはアクティブデッキから削除した。
- 前半はiPhone／iPadのウインドウサイズ適応、後半は異なるコンテキストに適応する動的コンポーネントを扱う。
- 表現はモデルとユースケースを主軸に決め、コンテナとプラットフォームは追加の文脈として扱う。
- AIは導入の主題から外し、第2章のモデル候補抽出を支援する例としてのみ扱う。
- 非アクティブな素材や旧稿は `DRAFT_NOTES.md` に保持する。アクティブデッキは構造整理済みで、画像TODOは解消済み。
- 約45分のリハーサルでは、まずiPhone／iPad比較、可変グリッド／ViewThatFits、タブバー／サイドバー、ニュースモデルのコンテキスト比較に必要な画像・実演時間を実測して使う。話者ノートを人工的に水増ししない。実演後も不足する場合だけ意味を表すAPIへの遷移を広げる。密度の高い構造とモデルの章、最終まとめは拡張ではなく圧縮候補とする。
- 初回圧縮後の削減素材は `DRAFT_NOTES.md` に「2026-07-27 初回時間圧縮で退避」として保持した。2026-07-27に「原稿量復元前」として復元前のアクティブデッキ全文も退避した。話者ノート整理後の現行は29スライド、`^` 話者ノート178行、画像TODOは解消済み。約45分目標に対して画像・実演時間は未算入のため、次はリハーサルで実測し、必要に応じて調整する。
- 2026-07-29に進捗を確認し、連続的なサイズ適応を扱う4枚と、構成変更・クロスコンテキストを扱う2枚の画像を `assets/adaptive-ui/` に追加して `iosdc2.md` へ接続した。画像TODOは解消済み。次はDecksetでの表示確認と、画像・実演を含めたリハーサルで時間を実測する。
- 2026-07-29の整理で、アクティブデッキの話者ノートを基本的に「です・ます」調へ統一し、第2章に残っていた断片的なメモ口調、アジェンダとの説明順のずれ、表示内容のないデザインデータスライド、末尾のコメントだけの空スライドを修正した。以後も話者ノートは表示内容を先に説明し、次のスライドへの遷移で閉じる。

## 執筆・編集ルール

- 現在のタイトルはCFPに提出済みのため変更しない。詳細な意図、章構成、表現はタイトルに狭く合わせるのではなく、確認済みの発表目標に沿って発展させる。
- 執筆中はMarkdown全体の分量から登壇時間を見積もらない。最後にDecksetの話者ノート（`^` で始まる段落）だけを抽出し、その話し言葉の文章を基準に時間を見積もって、約45分に収まるよう編集する。
- プロジェクトの判断、作成中のスライド内容、関連するコード例をチャット画面だけに残さない。完成前であっても、作業の進行に合わせてプロジェクトのMarkdownファイルへ記録し、リポジトリから再開できる状態にする。`iosdc2.md` を作業用のDecksetデッキ、`PROJECT_MEMORY.md` を永続的な判断・背景の記録として扱う。
- 表示するスライドは簡潔にし、短いタイトルと少数の箇条書き、または画像1枚・コード例1つを基本とする。
- 話者ノートは日本語で、会話調のスクリプトとして書く。導入や前のスライドからの遷移、説明する目的を示してから、短い段落で要点を伝える。
