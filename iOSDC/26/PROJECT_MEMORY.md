## プレゼンテーションの形式・内容

プレゼンテーションの内容は、主に Markdown のテキストファイルとして作成・管理する。
Deckset向けに、スライドは `---` で区切り、`^` で始まる段落はスライドに表示しない話者ノートとして扱う。

## 執筆・編集ルール

- 現在のタイトルはCFPに提出済みのため変更しない。詳細な意図、章構成、表現はタイトルに狭く合わせるのではなく、確認済みの発表目標に沿って発展させる。
- 執筆中はMarkdown全体の分量から登壇時間を見積もらない。最後にDecksetの話者ノート（`^` で始まる段落）だけを抽出し、その話し言葉の文章を基準に時間を見積もって、約45分に収まるよう編集する。
- プロジェクトの判断、作成中のスライド内容、関連するコード例をチャット画面だけに残さない。完成前であっても、作業の進行に合わせてプロジェクトのMarkdownファイルへ記録し、リポジトリから再開できる状態にする。`iosdc2.md` を作業用のDecksetデッキ、`PROJECT_MEMORY.md` を永続的な判断・背景の記録として扱う。
- 表示するスライドは簡潔にし、短いタイトルと少数の箇条書き、または画像1枚・コード例1つを基本とする。
- 話者ノートは日本語で、会話調のスクリプトとして書く。導入や前のスライドからの遷移、説明する目的を示してから、短い段落で要点を伝える。
